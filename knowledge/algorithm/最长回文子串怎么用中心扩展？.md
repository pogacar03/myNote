# 最长回文子串怎么用中心扩展？

对应 LeetCode 5：Longest Palindromic Substring。

## 现在的拆题方式

这题原理不难，真正容易乱的是代码职责拆分。

把问题只拆成两层：

```text
longestPalindrome：枚举所有可能的中心，并维护最长答案
expand：给定一个中心，只负责向左右扩展并返回长度
```

不要在 `expand` 里面再写“奇数回文 / 偶数回文”的 if。

奇偶两种情况直接由传参表示：

```java
expand(s, i, i);      // 一个点作为中心：奇数长度
expand(s, i, i + 1);  // 两个点之间作为中心：偶数长度
```

## 最新写法

```java
class Solution {
    public String longestPalindrome(String s) {
        int maxLen = 1;
        int len = 1;
        int n = s.length();
        int start = 0;

        for (int i = 0; i < n - 1; i++) {
            int len1 = expand(s, i, i);
            int len2 = expand(s, i, i + 1);

            len = Math.max(len1, len2);

            if (len > maxLen) {
                maxLen = len;
                start = i - (maxLen - 1) / 2;
            }
        }

        return s.substring(start, start + maxLen);
    }

    public int expand(String s, int left, int right) {
        while (left >= 0
                && right < s.length()
                && s.charAt(left) == s.charAt(right)) {
            left--;
            right++;
        }

        return right - left + 1 - 2;
    }
}
```

`right - left + 1 - 2` 等价于：

```java
right - left - 1
```

## 为什么 expand 返回 `right - left - 1`

循环中：

```java
while (left >= 0
        && right < s.length()
        && s.charAt(left) == s.charAt(right)) {
    left--;
    right++;
}
```

当 while 停止时，`left` 和 `right` 已经各自多走了一步。

例如合法回文实际范围是：

```text
[left + 1, right - 1]
```

所以长度为：

```text
(right - 1) - (left + 1) + 1
= right - left - 1
```

也就是代码里的：

```java
return right - left + 1 - 2;
```

## 为什么起点是 `i - (maxLen - 1) / 2`

当前中心由 `i` 表示，拿到最长长度 `maxLen` 后，可以反推出回文串起点：

```java
start = i - (maxLen - 1) / 2;
```

这个公式同时兼容奇数和偶数回文。

例如奇数长度 3：

```text
中心 i = 2
长度 = 3
start = 2 - (3 - 1) / 2 = 1
```

偶数长度 4 时，由 `expand(i, i + 1)` 得到：

```text
start = i - (4 - 1) / 2
      = i - 1
```

同样正确。

## 最重要的拆分粒度

主函数不要负责“怎么扩”。

它只做四件事：

```text
1. 枚举 i
2. 调一次 expand(i, i)
3. 调一次 expand(i, i + 1)
4. 取最大长度并更新 start / maxLen
```

`expand` 也不要负责全局答案，它只做一件事：

```text
左右字符相等就继续扩，最后返回这一中心能得到的最大回文长度。
```

所以可以记成：

```text
for = 枚举中心
expand = 处理一个确定的中心
```

## 易错点

### 1. 两种中心都必须检查

```java
int len1 = expand(s, i, i);
int len2 = expand(s, i, i + 1);
```

分别对应：

```text
aba   -> i, i
abba  -> i, i + 1
```

### 2. while 退出时已经多扩了一步

所以不是：

```java
right - left + 1
```

而是：

```java
right - left - 1
```

### 3. start 根据长度算，不是根据 i 自己算

正确：

```java
start = i - (maxLen - 1) / 2;
```

错误思路：

```java
start = i - (i - 1) / 2;
```

因为起点取决于“当前回文有多长”，不是取决于 i 的数值。

### 4. 循环边界

当前代码写：

```java
for (int i = 0; i < n - 1; i++)
```

在题目字符串非空、`maxLen` 初始为 1 的情况下可以工作，因为最后一个位置最多单独形成长度 1，无法刷新答案。

更通用、也更容易理解的模板可以直接写：

```java
for (int i = 0; i < n; i++)
```

`expand(s, i, i + 1)` 自己会通过 `right < s.length()` 处理越界。

### 5. 为什么 `expand(s, i, i + 1)` 最后一轮不会越界报错

如果字符串长度是 10，合法下标是 `0 ~ 9`。

当 `i = 9` 时会调用：

```java
expand(s, 9, 10);
```

这里 `right = 10` 的确已经超出合法下标，但这只是“传进来的参数值”越界，还没有真正访问字符串。

真正访问 `s.charAt(right)` 之前，`while` 会先判断：

```java
left >= 0
&& right < s.length()
&& s.charAt(left) == s.charAt(right)
```

此时：

```text
right < s.length()
10 < 10
false
```

因为 Java 的 `&&` 有短路特性，前面的条件一旦为 `false`，后面的：

```java
s.charAt(right)
```

就不会执行，所以不会发生越界异常。

因此可以记住：

```text
参数本身可以暂时越界，
但真正访问数组 / 字符串之前必须先做边界判断。
```

也正因为如此，边界条件要放在字符访问前面：

```java
left >= 0
&& right < s.length()
&& s.charAt(left) == s.charAt(right)
```

不要把 `charAt` 判断放到前面。

## 复杂度

```text
时间复杂度：O(n²)
空间复杂度：O(1)
```

## 一句话记忆

```text
每个 i 尝试两个中心：
(i, i) 和 (i, i+1)

主函数负责枚举和选最大值；
expand 只负责向两边扩并返回长度。

即使最后一次 i+1 == s.length()，
expand 也会先做 right < s.length() 的边界判断，
&& 短路后不会真正执行 charAt(right)。
```
